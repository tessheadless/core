Tess vs Payload

CMS headless «code-first» (TypeScript, Next.js)

Un CMS de código abierto en TypeScript que se configura en código y se instala dentro de una aplicación Next.js.

Cara a cara

Tess comparado con Payload
CriterioTessPayload
Modelos de contenidoSe definen en tiempo de ejecución en el panel o la APISe definen en archivos de configuración TypeScript y se despliegan con la aplicación
Entorno de ejecuciónBinario de Rust independiente, cualquier tecnología de front-endSe ejecuta dentro de una aplicación Next.js (Node.js)
APIGraphQL generado a partir de los modelosREST, GraphQL y una API local de Node.js
Bases de datosPostgreSQL, MySQL, SQLite, MongoDB, DynamoDB, RocksDBMongoDB, PostgreSQL, SQLite
ExtensibilidadPlugins WebAssembly aisladosHooks y plugins de TypeScript en la aplicación
LicenciaCommunity (uso personal) / Enterprise (uso comercial)MIT

Elige Payload si…

  • Tu proyecto es una aplicación Next.js y quieres el esquema en tu repositorio, en TypeScript.

Elige Tess si…

  • Los administradores deben hacer evolucionar los modelos sin desarrolladores ni despliegues.
  • No todos tus front-ends son JavaScript, o quieres el CMS separado de la aplicación.

Pasar de Payload a Tess

Las colecciones y los blocks de Payload se corresponden con tipos de contenido y componentes de Tess (los campos blocks pasan a ser DYNAMIC_ZONE). Traduce la configuración al formato YAML de tess-transfer, impórtala y copia los documentos mediante las API GraphQL.
