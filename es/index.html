CMS headless · Rust · GraphQL · MCP

Cada entrada es una tesela. Tus aplicaciones son el mosaico.

Tess es un CMS headless autoalojable en un único binario de Rust. Define tus modelos de contenido en tiempo de ejecución y obtén al instante una API GraphQL tipada, sobre la base de datos que ya usas. Y gestiónalo todo hablando con tu asistente de IA, gracias al servidor MCP integrado.

Empieza en 5 minutosComparar con otros CMS
graphql
query {
  posts(where: { title_contains: "tess" }, first: 3) {
    total
    items {
      title
      publishedAt
      authors { name }
    }
  }
}

Gestiona tu sitio web hablando con tu IA

Pide a Claude, Cursor o cualquier cliente MCP que escriba, edite y publique tu contenido: Tess habla el Model Context Protocol desde el primer momento. Tu asistente descubre por sí mismo tus modelos de contenido y luego lee y escribe con la misma API y los mismos permisos que tus aplicaciones.

  • Sin plugins ni código de integración: actívalo con TESS_MCP=true y añade una entrada a tu cliente de IA.
  • Seguro por defecto: dale al asistente un token Contributor y solo podrá escribir borradores, que tu equipo revisa y publica.
  • Funciona con cada modelo que creas, en cuanto lo creas.

Todo lo que necesita un equipo de contenido, nada que reconstruir

Tess mantiene las reglas de negocio en un solo lugar, así que la API GraphQL, el panel de administración, las subidas y los plugins se comportan igual.

  • Gestionado con IA

    Un servidor MCP integrado permite a Claude, Cursor y cualquier cliente MCP leer tus modelos y crear, editar y publicar contenido en lenguaje natural, con los mismos permisos que la API.

  • Modelos en tiempo de ejecución

    Crea tipos de contenido en el panel de administración o mediante la API, en producción. El esquema GraphQL se regenera al momento: sin recompilar ni volver a desplegar.

  • GraphQL primero

    Consultas tipadas, filtros, ordenación, paginación, relaciones y mutaciones generadas para cada modelo, con el IDE GraphiQL integrado.

  • Tu base de datos

    PostgreSQL, MySQL, SQLite, MongoDB, DynamoDB o RocksDB integrado. Todos los backends pasan la misma batería de pruebas de conformidad.

  • Flujos de revisión

    Borrador y publicación para cada entrada, más un flujo opcional enviar → aprobar por tipo de contenido, en todas las ediciones.

  • Plugins aislados

    Plugins WebAssembly que los administradores instalan en tiempo de ejecución, escritos en Rust, Go, JavaScript y más, con límites de tiempo y de memoria.

Un modelo de contenido está a una mutación

Crea un tipo de contenido y Tess genera al instante sus consultas, filtros, ordenación, paginación y mutaciones, en cada instancia.

¿Prefieres hacer clic? El panel de administración tiene un editor de modelos. ¿Prefieres archivos? Guarda tus modelos en YAML e impórtalos con tess-transfer.

graphql
mutation {
  createContentType(input: {
    apiId: "Post"
    workflow: true
    fields: [
      { name: "title", type: TEXT, required: true }
      { name: "body", type: MARKDOWN }
      { name: "cover", type: RELATION, relationTarget: "Asset" }
      { name: "authors", type: RELATION, relationTarget: "Author", many: true }
    ]
  }) { apiId }
}

Dato curioso: Tess funciona en una Raspberry Pi 3

Quien creó Tess tiene su propia instancia funcionando en una Raspberry Pi 3, sin n8n: un binario de Rust, una base de datos integrada y nada más que instalar. En reposo usa unos 30 MB de memoria, así que incluso una placa de 1 GB tiene margen de sobra.

  • Sin servidor de base de datos: RocksDB y SQLite vienen integrados.
  • Versiones ARM nativas: binarios arm64 y armv7 e imágenes Docker arm64 en cada versión.
  • También Pi 4 y 5, con espacio para n8n, PostgreSQL y búsqueda en las placas más grandes.

Ejecuta Tess en una Raspberry Pi →

shell
# En la Pi (Raspberry Pi OS de 64 bits)
VERSION=0.1.1
curl -LO https://github.com/tessheadless/core/releases/download/v$VERSION/tess-$VERSION-linux-arm64.tar.xz
tar -xJf tess-$VERSION-linux-arm64.tar.xz
cd tess-$VERSION-linux-arm64

cp .env.example .env   # añade tus secretos
set -a && . ./.env && set +a && ./tess
# → http://raspberrypi.local:8080/admin/

Preguntas

¿Tess es gratis?

La edición Community es gratuita para uso personal. El uso comercial requiere la edición Enterprise, que además añade funciones avanzadas, plugins oficiales y alojamiento. Consulta Community y Enterprise (en inglés).

¿Pueden las herramientas de IA gestionar mi contenido?

Sí. Tess tiene un servidor MCP integrado: conecta Claude, Cursor o cualquier cliente MCP con un token de API y pídele en lenguaje natural que cree, edite, traduzca o publique contenido. Puede hacer exactamente lo que permite el rol del token, nada más.

¿Qué base de datos necesito?

Ninguna para empezar: Tess integra RocksDB. En producción usa PostgreSQL, MySQL, MongoDB o DynamoDB, o quédate con SQLite o RocksDB para sitios pequeños.

¿Puede Tess funcionar en una Raspberry Pi?

Sí. Quien creó Tess lo tiene funcionando en una Raspberry Pi 3. Cada versión incluye binarios nativos de Linux arm64 y armv7 e imágenes Docker arm64, para las Pi 3, 4 y 5. Consulta Raspberry Pi y dispositivos pequeños (en inglés).

¿Hay una API REST?

El contenido se sirve solo mediante GraphQL. Existen endpoints REST para datos binarios: subida y descarga de archivos multimedia y módulos de plugins.

¿Puedo traer mis modelos desde otro CMS?

Descríbelos en el formato YAML de tess-transfer e impórtalos con un solo comando. Cada página de comparación explica cómo se traslada un modelo a Tess.

Ejecuta Tess con un solo comando

docker compose up, abre el panel de administración y crea tu primer modelo.
