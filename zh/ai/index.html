内置 MCP 服务器

和你的 AI 对话，就能管理你的网站。

Tess 支持 Model Context Protocol，这是 AI 助手调用工具时使用的开放标准。两分钟内连接 Claude、Codex、OpenCode、Pi 或任何 MCP 客户端，然后用自然语言提出要求：“为我们的新版本起草一篇文章”、“修正价格页上的错别字”、“哪些产品没有图片？”。无需安装插件，无需编写代码。

连接你的 AI5 分钟上手
chat
你：  找出所有缺少 meta description 的
      已发布文章，为每篇写一段，存为草稿。

AI：  找到 12 篇文章。我已为每篇起草了
      描述，并提交审核。

你：  下周在首页加一个“夏季特卖”横幅，
      然后给我看看草稿。

你可以提出的要求

你的助手会先读取内容模型，因此无需任何设置就了解你的字段、关联和组件。然后它就像一位永不疲倦的编辑：

  • 撰写： “根据这些发布说明起草三篇博客文章，附上摘要和标签。”
  • 批量编辑： “所有超过 300 字的产品描述：缩短它们，保持原有语气。”
  • 检查： “哪些已发布页面缺少 meta description 或封面图？”
  • 建模： “添加一个 FAQ 内容类型，包含问题、答案和分类。”（需要 Admin 令牌）
  • 发布： “发布我今天上午批准的草稿。”
  • 回答问题： “今年我们每个月发布了多少篇文章？”

它适用于你创建的每个内容模型，创建后立即可用：MCP 服务器通过 get_schema 和 graphql_query 两个通用工具开放你完整的 GraphQL API。

两分钟完成设置

  1. 在服务器设置中 开启它：TESS_MCP=true。
  2. 在管理后台（API tokens）为你的助手 创建一个 API 令牌，并赋予所需角色：Contributor 可写草稿，Member 只能读取。
  3. 把 Tess 添加到你的 AI 客户端：填入服务器 URL，并把令牌放在 Authorization: Bearer 请求头中，如示例所示。Claude Code、OpenCode、Codex 和 Pi 都只需一行配置。

就这样：你的助手现在可以看到你的内容，权限与它的令牌完全一致。对于只能运行本地程序的客户端（例如 Claude Desktop），tess mcp 命令会通过一个小型本地代理实现同样的功能。

{
  "mcpServers": {
    "tess": {
      "type": "http",
      "url": "https://cms.example.com/mcp",
      "headers": { "Authorization": "Bearer tess_t1_…" }
    }

}

为你工作的 AI，而不是绕过你的 AI

让 AI 访问你的网站，不应该意味着失去控制。使用 Tess 就不会：

  • 人人遵守同样的规则。 助手使用 API 令牌，Tess 对每次调用都应用该令牌的角色和范围。Member 令牌只能读取；Contributor 令牌只能在你允许的内容类型中写草稿。
  • 最终决定权在人手中。 启用审核工作流后，AI 的修改是提交审核的草稿：在任何内容上线前，都由你的团队批准。
  • 一切都有记录。 每次修改都会记录是谁做的，因此你随时知道助手做了什么，并可以一键撤销它的令牌。
  • 你的数据始终属于你。 Tess 运行在你的服务器上，只与你连接的 AI 客户端通信，且只提供其令牌可访问的内容。

关于 AI 与 MCP 的问题

哪些 AI 工具可以配合 Tess 使用？

任何支持 Model Context Protocol 的客户端：Claude Code、Claude Desktop、OpenCode、Codex、Pi、Cursor 等。支持远程服务器的客户端可直接连接 https://your-server/mcp，并在 Authorization: Bearer 请求头中携带 API 令牌；其他客户端（如 Claude Desktop）则运行本地的 tess mcp 代理。MCP 指南（英文）提供了每个客户端的配置。

我的 AI 助手如何登录 Tess？

使用你在管理后台创建的 API 令牌。客户端在每个请求的 Authorization: Bearer 请求头中发送它，因此 Tess 知道是哪个令牌、哪个角色在调用。请把令牌放在环境变量中而不是配置文件里，必要时可一键撤销。没有令牌时，助手只能读取已发布的内容。

MCP 服务器包含在 Community 版中吗？

包含。它内置于 Tess 的所有版本中：无需附加组件，也无需额外服务。在你设置 TESS_MCP=true 之前，它处于关闭状态。

AI 会删除或破坏我的内容吗？

只有当你给它的令牌允许这样做时才会。请使用限定在少数内容类型上的 Contributor 令牌，并开启审核工作流：这样 AI 只会写草稿，由你的团队审核并发布。

它能配合我自己的内容模型使用吗？

能，所有模型都可以，创建后立即可用。助手会先读取你的 schema，所以无需为每个模型单独配置。

安装 Tess，开启 MCP 服务器，然后让你的助手写出第一篇草稿。
