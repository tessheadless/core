Tess 对比 Payload

代码优先的无头 CMS（TypeScript、Next.js）

一款在代码中配置的开源 TypeScript CMS，安装在 Next.js 应用内部。

逐项对比

Tess 与 Payload 的对比
对比项TessPayload
内容模型在运行时通过管理后台或 API 定义在 TypeScript 配置文件中定义，随应用部署
运行环境独立的 Rust 二进制文件，前端技术栈任选运行在 Next.js（Node.js）应用内部
API根据模型生成的 GraphQLREST、GraphQL 和本地 Node.js API
数据库PostgreSQL、MySQL、SQLite、MongoDB、DynamoDB、RocksDBMongoDB、PostgreSQL、SQLite
可扩展性沙箱 WebAssembly 插件应用中的 TypeScript 钩子和插件
许可证Community（个人使用）/ Enterprise（商业使用）MIT

以下情况选择 Payload…

  • 你的项目是 Next.js 应用，并且希望 schema 以 TypeScript 形式保存在代码仓库中。

以下情况选择 Tess…

  • 管理员必须能在没有开发人员、无需重新部署的情况下改进模型。
  • 你的前端并非都用 JavaScript，或者你希望 CMS 与应用分离。

从 Payload 迁移到 Tess

Payload 的 collection 和 block 对应为 Tess 的内容类型和组件（blocks 字段变为 DYNAMIC_ZONE）。把配置转换为 tess-transfer 的 YAML 格式并导入，再通过 GraphQL API 复制文档。
