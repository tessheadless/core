对比

Tess 与其他 CMS 的对比

每个 CMS 都有取舍。这些页面说明 Tess 适合哪些场景，以及何时其他产品是更好的选择。每一页都会介绍如何把你的内容模型迁移到 Tess。

  • Tess 对比 Strapi

    开源无头 CMS（Node.js）

    最受欢迎的开源无头 CMS，基于 Node.js 构建，提供 REST API 和 GraphQL 插件。

    要点：Tess 与 Strapi
    对比项TessStrapi
    运行环境单个 Rust 二进制文件Node.js（TypeScript）应用
    内容模型在生产环境中运行时创建（管理后台或 API）；GraphQL schema 实时重新生成开发模式下使用 Content-Type Builder；模型保存为代码文件，随应用部署
    API根据模型生成的 GraphQL默认 REST，GraphQL 通过官方插件提供
    迁移指南：从 Strapi 迁移到 Tess完整对比

  • Tess 对比 Hygraph

    原生 GraphQL 无头 CMS（SaaS）

    一款托管式、原生 GraphQL 的 CMS（前身为 GraphCMS），以跨远程 API 的内容联合著称。

    要点：Tess 与 Hygraph
    对比项TessHygraph
    交付方式由你自己运行的软件仅提供托管 SaaS
    API根据模型生成的 GraphQL根据模型生成的 GraphQL，支持远程数据源的内容联合
    内容模型管理后台或 API，立即生效Web 应用中的 schema 编辑器，支持多环境
    迁移指南：从 Hygraph 迁移到 Tess完整对比

  • Tess 对比 WordPress

    传统 CMS（PHP），可用作无头 CMS

    全球使用最广泛的 CMS，一个带主题、插件和 REST API 的 PHP 应用，常通过 WPGraphQL 以无头方式使用。

    要点：Tess 与 WordPress
    对比项TessWordPress
    架构无头：只管内容，前端任选带主题的一体化建站工具；可通过其 API 以无头方式使用
    内容模型带校验的类型化模型，在管理后台或 API 中定义文章和页面；自定义文章类型和字段需通过代码或 ACF 等插件实现
    API根据模型生成的 GraphQL内置 REST API；GraphQL 通过 WPGraphQL 插件提供
    迁移指南：从 WordPress 迁移到 Tess完整对比

  • Tess 对比 Contentful

    可组合内容平台（SaaS）

    以 SaaS 形式提供的企业级无头 CMS，提供 REST 和 GraphQL 内容分发 API 以及庞大的应用生态。

    要点：Tess 与 Contentful
    对比项TessContentful
    交付方式由你自己运行的软件仅提供托管 SaaS
    API根据模型生成的 GraphQLREST 分发与管理 API，外加 GraphQL Content API
    内容模型管理后台或 API，立即生效Web 应用或管理 API，支持多环境
    从 Contentful 迁移：导入与导出工具完整对比

  • Tess 对比 Directus

    基于 SQL 数据库的数据平台（Node.js）

    一个 Node.js 平台，可把现有 SQL 数据库变成 REST 和 GraphQL API，并附带管理应用。

    要点：Tess 与 Directus
    对比项TessDirectus
    思路Tess 管理自己的存储和 schema映射现有 SQL 数据库的表
    数据库PostgreSQL、MySQL、SQLite、MongoDB、DynamoDB、RocksDBSQL 数据库：PostgreSQL、MySQL、MariaDB、SQLite、MS SQL、Oracle、CockroachDB
    API根据模型生成的 GraphQLREST 和 GraphQL
    从 Directus 迁移：导入与导出工具完整对比

  • Tess 对比 Payload

    代码优先的无头 CMS（TypeScript、Next.js）

    一款在代码中配置的开源 TypeScript CMS，安装在 Next.js 应用内部。

    要点：Tess 与 Payload
    对比项TessPayload
    内容模型在运行时通过管理后台或 API 定义在 TypeScript 配置文件中定义，随应用部署
    运行环境独立的 Rust 二进制文件，前端技术栈任选运行在 Next.js（Node.js）应用内部
    API根据模型生成的 GraphQLREST、GraphQL 和本地 Node.js API
    从 Payload 迁移：导入与导出工具完整对比

  • Tess 对比 Sanity

    带开源编辑工作室的托管内容平台

    一个托管的 Content Lake，配有可定制的开源 React 编辑工作室，以及自有查询语言 GROQ。

    要点：Tess 与 Sanity
    对比项TessSanity
    交付方式由你自己运行的软件托管的 Content Lake；工作室开源，可自行部署
    内容模型管理后台或 API，立即生效用 JavaScript/TypeScript 代码编写 schema
    API根据模型生成的 GraphQLGROQ，外加可部署的 GraphQL API
    从 Sanity 迁移：导入与导出工具完整对比
