Tess 对比 Strapi

开源无头 CMS（Node.js）

最受欢迎的开源无头 CMS，基于 Node.js 构建，提供 REST API 和 GraphQL 插件。

逐项对比

Tess 与 Strapi 的对比
对比项TessStrapi
运行环境单个 Rust 二进制文件Node.js（TypeScript）应用
内容模型在生产环境中运行时创建（管理后台或 API）；GraphQL schema 实时重新生成开发模式下使用 Content-Type Builder；模型保存为代码文件，随应用部署
API根据模型生成的 GraphQL默认 REST，GraphQL 通过官方插件提供
数据库PostgreSQL、MySQL、SQLite、MongoDB、DynamoDB、RocksDBPostgreSQL、MySQL/MariaDB、SQLite
审核工作流按内容类型设置，所有版本均可用包含草稿与发布；审核工作流需付费方案
插件运行时安装的沙箱 WebAssembly 模块在应用进程中运行的 Node.js 包，插件市场庞大
本地化暂不支持按字段的内容本地化内置内容国际化
托管自托管：Docker、虚拟机、Kubernetes 或 AWS Lambda自托管或 Strapi Cloud
许可证Community（个人使用）/ Enterprise（商业使用）Community Edition 采用 MIT；企业功能需付费方案

以下情况选择 Strapi…

  • 你需要庞大的插件市场和社区。
  • 你现在就需要本地化内容。
  • 你的团队更喜欢用 JavaScript/TypeScript 定制 CMS 本身。

以下情况选择 Tess…

  • 编辑或管理员必须 在生产环境中 修改模型，而无需重新部署。
  • 你希望在 MongoDB、DynamoDB 或内嵌数据库上使用 GraphQL 优先的 API。
  • 你希望不付费也能使用审核工作流，或在 AWS Lambda 上运行。

从 Strapi 迁移到 Tess

Strapi 的类型与 Tess 一一对应：string/text → TEXT、richtext → MARKDOWN、blocks → JSON、enumeration → ENUM、relation → RELATION、media → 指向 Asset 的 RELATION、component → COMPONENT、dynamiczone → DYNAMIC_ZONE。用 tess-transfer 的 YAML 格式编写模型，一条命令导入，再通过 GraphQL API 复制条目。
