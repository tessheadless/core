无头 CMS · Rust · GraphQL · MCP

每个条目都是一块瓷砖，你的应用就是那幅马赛克。

Tess 是一款可自托管的无头 CMS，只需一个 Rust 二进制文件。在运行时定义内容模型，立即在你已有的数据库上获得带类型的 GraphQL API。还能通过内置的 MCP 服务器，和你的 AI 助手对话来管理一切。

5 分钟上手与其他 CMS 对比
graphql
query {
  posts(where: { title_contains: "tess" }, first: 3) {
    total
    items {
      title
      publishedAt
      authors { name }
    }
  }
}

和你的 AI 对话，管理你的网站

让 Claude、Cursor 或任何 MCP 客户端撰写、编辑和发布你的内容：Tess 开箱即支持 Model Context Protocol。你的助手会自己发现内容模型，然后通过与你的应用相同的 API 和权限进行读写。

  • 无需插件，无需胶水代码： 设置 TESS_MCP=true 即可开启，再在 AI 客户端里加一条配置。
  • 默认安全： 给助手一个 Contributor 令牌，它就只能写草稿，由你的团队审核并发布。
  • 适用于你创建的每个模型，创建后立即可用。

了解工作原理 →

chat
你：  找出所有缺少 meta description 的
      已发布文章，为每篇写一段，存为草稿。

      然后给我看看草稿。

内容团队需要的一切，无需重新开发

Tess 把业务规则集中在一处，因此 GraphQL API、管理后台、上传和插件的行为完全一致。

  • 交给 AI 来运营

    内置的 MCP 服务器让 Claude、Cursor 和任何 MCP 客户端读取你的模型，并用自然语言创建、编辑和发布内容，权限与 API 完全相同。

  • 运行时定义模型

    在生产环境中通过管理后台或 API 创建内容类型。GraphQL schema 即时重新生成：无需重新构建，无需重新部署。

  • GraphQL 优先

    为每个模型生成带类型的查询、过滤、排序、分页、关联和 mutation，并内置 GraphiQL IDE。

  • 用你自己的数据库

    PostgreSQL、MySQL、SQLite、MongoDB、DynamoDB 或内嵌的 RocksDB。每个后端都通过同一套一致性测试。

  • 审核工作流

    每个条目都有草稿和发布，每种内容类型还可选用“提交 → 批准”工作流，所有版本均可用。

  • 沙箱插件

    由管理员在运行时安装的 WebAssembly 插件，可用 Rust、Go、JavaScript 等语言编写，带有超时和内存限制。

一个 mutation 就是一个内容模型

创建一个内容类型，Tess 立即在每个实例上生成它的查询、过滤、排序、分页和 mutation。

喜欢点鼠标？管理后台有模型编辑器。喜欢用文件？把模型保存为 YAML，再用 tess-transfer 导入。

graphql
mutation {
  createContentType(input: {
    apiId: "Post"
    workflow: true
    fields: [
      { name: "title", type: TEXT, required: true }
      { name: "body", type: MARKDOWN }
      { name: "cover", type: RELATION, relationTarget: "Asset" }
      { name: "authors", type: RELATION, relationTarget: "Author", many: true }
    ]
  }) { apiId }
}

趣闻：Tess 跑在一台树莓派 3 上

Tess 的作者自己的 Tess 就运行在一台 树莓派 3（Raspberry Pi 3） 上，没有 n8n：一个 Rust 二进制文件、一个内嵌数据库，别的什么都不用装。空闲时它只占用约 30 MB 内存，即使是 1 GB 内存的板子也绰绰有余。

  • 无需数据库服务器： 内置 RocksDB 和 SQLite。
  • 原生 ARM 版本： 每次发布都提供 arm64 和 armv7 二进制文件以及 arm64 Docker 镜像。
  • 树莓派 4 和 5 也可以，内存更大的型号还能同时运行 n8n、PostgreSQL 和搜索。

在树莓派上运行 Tess →

shell
# 在树莓派上（64 位 Raspberry Pi OS）
VERSION=0.1.1
curl -LO https://github.com/tessheadless/core/releases/download/v$VERSION/tess-$VERSION-linux-arm64.tar.xz
tar -xJf tess-$VERSION-linux-arm64.tar.xz
cd tess-$VERSION-linux-arm64

cp .env.example .env   # 填入你的密钥
set -a && . ./.env && set +a && ./tess
# → http://raspberrypi.local:8080/admin/

常见问题

Tess 免费吗？

Community 版对个人使用免费。商业使用需要 Enterprise 版，它还提供高级功能、官方插件和托管服务。参见 Community 与 Enterprise（英文）。

AI 工具能管理我的内容吗？

可以。Tess 内置 MCP 服务器：用 API 令牌连接 Claude、Cursor 或任何 MCP 客户端，然后用自然语言让它创建、编辑、翻译或发布内容。它能做的正是令牌角色所允许的，不多也不少。

我需要什么数据库？

入门时什么都不需要：Tess 内嵌 RocksDB。生产环境可使用 PostgreSQL、MySQL、MongoDB 或 DynamoDB，小型网站也可以继续使用 SQLite 或 RocksDB。

Tess 能在树莓派上运行吗？

可以。Tess 的作者就把它运行在一台树莓派 3 上。每次发布都提供原生的 arm64 和 armv7 Linux 二进制文件以及 arm64 Docker 镜像，适用于树莓派 3、4 和 5。参见 树莓派与小型设备（英文）。

有 REST API 吗？

内容只通过 GraphQL 提供。REST 端点仅用于二进制数据：媒体上传与下载、插件模块。

能把我的模型从其他 CMS 迁移过来吗？

用 tess-transfer 的 YAML 格式描述它们，一条命令即可导入。每个 对比页面 都说明了模型如何对应到 Tess。

一条命令运行 Tess

docker compose up，打开管理后台，创建你的第一个模型。
