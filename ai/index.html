Built-in MCP server

Your website, managed by talking to your AI.

Tess speaks the Model Context Protocol, the open standard AI assistants use to work with tools. Connect Claude, Codex, OpenCode, Pi or any MCP client in two minutes, then ask in plain language: “draft a post about our new release”, “fix the typos on the pricing page”, “which products have no image?”. No plugin to install, no code to write.

What you can ask

Your assistant reads your content models first, so it knows your fields, relations and components without any setup. Then it works like an editor who never gets tired:

  • Write: “Draft three blog posts from these release notes, with a summary and tags.”
  • Edit at scale: “Every product description over 300 words: shorten it and keep the tone.”
  • Check: “Which published pages have no meta description or no cover image?”
  • Model: “Add an FAQ content type with a question, an answer and a category.” (with an Admin token)
  • Publish: “Publish the drafts I approved this morning.”
  • Answer questions: “How many articles did we publish per month this year?”

It works with every content model you create, the moment you create it: the MCP server exposes your whole GraphQL API through two generic tools, get_schema and graphql_query.

Set up in two minutes

  1. Turn it on in your server settings: TESS_MCP=true.
  2. Create an API token for your assistant in the admin (API tokens), with the role it needs: Contributor to write drafts, Member to read only.
  3. Add Tess to your AI client: the URL of your server, and the token in an Authorization: Bearer header, as shown here. Claude Code, OpenCode, Codex and Pi each take it in one line of their configuration.

That's it: your assistant now sees your content, with exactly the rights of its token. For clients that only run local programs, like Claude Desktop, the tess mcp command does the same through a small local proxy.

AI that works for you, not around you

Giving an AI access to your website should not mean giving up control. With Tess it doesn't:

  • The same rules as everyone. The assistant uses an API token, and Tess applies that token's role and scope to every call. A Member token reads; a Contributor token writes drafts, only on the content types you allow.
  • Humans keep the last word. With review workflows, the AI's changes are drafts submitted for review: your team approves them before anything goes live.
  • Everything is traced. Each change records who made it, so you always know what the assistant did, and can revoke its token in one click.
  • Your data stays yours. Tess runs on your servers and talks only to the AI client you connect, with only the content its token can reach.

Questions about AI and MCP

Which AI tools work with Tess?

Any client that supports the Model Context Protocol: Claude Code, Claude Desktop, OpenCode, Codex, Pi, Cursor and more. Clients that support remote servers connect to https://your-server/mcp directly, with your API token in an Authorization: Bearer header; others, like Claude Desktop, run the local tess mcp proxy. The MCP guide has the configuration of each one.

How does my AI assistant sign in to Tess?

With an API token you create in the admin. The client sends it in the Authorization: Bearer header of every request, so Tess knows which token, and which role, is calling. Keep it in an environment variable rather than in a config file, and revoke it in one click if needed. Without a token, an assistant can only read published content.

Is the MCP server part of the Community edition?

Yes. It's built into Tess, in every edition: no add-on, no extra service. It's off until you set TESS_MCP=true.

Can the AI delete or break my content?

Only if you give it a token that allows it. Use a Contributor token scoped to a few content types, and enable review workflows: the AI then writes drafts that your team reviews and publishes.

Does it work with my own content models?

Yes, with all of them, as soon as you create them. The assistant reads your schema first, so there is nothing to configure per model.
