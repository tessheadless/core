Tess vs WordPress

Traditional CMS (PHP), usable headless

The world's most used CMS, a PHP application with themes, plugins and a REST API, often used headless through WPGraphQL.

Side by side

Tess compared with WordPress
CriterionTessWordPress
ArchitectureHeadless: content only, any front endMonolithic site builder with themes; headless through its APIs
Content modelsTyped models with validation, defined in the admin or APIPosts and pages; custom post types and fields through code or plugins such as ACF
APIGraphQL generated from the modelsREST API built in; GraphQL through the WPGraphQL plugin
StackRust binary, six database backendsPHP with MySQL or MariaDB
Editorial workflowDraft, review, publish per content typeDraft, pending review and publish; more through plugins
ExtensibilitySandboxed WebAssembly pluginsTens of thousands of PHP plugins and themes
LicenseCommunity (personal use) / Enterprise (commercial use)GPLv2 or later

Choose WordPress if…

  • You want a website with themes, built by non-developers.
  • You rely on a specific WordPress plugin or the huge ecosystem.

Choose Tess if…

  • Your content feeds several front ends (sites, mobile apps, kiosks).
  • You want structured, validated content and a typed API instead of posts and meta fields.

Moving from WordPress to Tess

Model your post types and custom fields as Tess content types (ACF field groups map well to components), import them with tess-transfer, then move the posts from the WordPress REST API to the Tess GraphQL API with a short script.
