Headless CMS · Rust · GraphQL · MCP

Every entry is a tile. Your apps are the mosaic.

Tess is a self-hostable headless CMS in a single Rust binary. Define your content models at runtime and get a typed GraphQL API instantly, on the database you already run. And manage it all by talking to your AI assistant, through the built-in MCP server.

Start in 5 minutesCompare with other CMSs
graphql
query {
  posts(where: { title_contains: "tess" }, first: 3) {
    total
    items {
      title
      publishedAt
      authors { name }
    }
  }
}

Manage your website by talking to your AI

Ask Claude, Cursor or any MCP client to write, edit and publish your content: Tess speaks the Model Context Protocol out of the box. Your assistant discovers your content models by itself, then reads and writes through the same API and permissions as your apps.

  • No plugin, no glue code: turn it on with TESS_MCP=true and add one entry to your AI client.
  • Safe by default: give the assistant a Contributor token and it can only write drafts, which your team reviews and publishes.
  • Works with every model you create, the moment you create it.

Everything a content team needs, nothing to rebuild

Tess keeps the business rules in one place, so the GraphQL API, the admin UI, uploads and plugins all behave the same.

  • Run it with AI

    A built-in MCP server lets Claude, Cursor and any MCP client read your models and create, edit and publish content in plain language, with the same permissions as the API.

  • Models at runtime

    Create content types in the admin or through the API, in production. The GraphQL schema is regenerated on the fly: no rebuild, no redeploy.

  • GraphQL-first

    Typed queries, filters, sorting, pagination, relations and mutations generated for every model, with a GraphiQL IDE built in.

  • Your database

    PostgreSQL, MySQL, SQLite, MongoDB, DynamoDB or embedded RocksDB. Every backend passes the same conformance suite.

  • Review workflows

    Draft and publish for every entry, plus an optional submit → approve workflow per content type, in every edition.

  • Sandboxed plugins

    WebAssembly plugins installed by admins at runtime, written in Rust, Go, JavaScript and more, with timeouts and memory limits.

A content model is one mutation away

Create a content type and Tess generates its queries, filters, sorting, pagination and mutations on the spot, on every instance.

Prefer clicking? The admin UI has a model editor. Prefer files? Keep your models in YAML and import them with tess-transfer.

graphql
mutation {
  createContentType(input: {
    apiId: "Post"
    workflow: true
    fields: [
      { name: "title", type: TEXT, required: true }
      { name: "body", type: MARKDOWN }
      { name: "cover", type: RELATION, relationTarget: "Asset" }
      { name: "authors", type: RELATION, relationTarget: "Author", many: true }
    ]
  }) { apiId }
}

Fun fact: Tess runs on a Raspberry Pi 3

Tess's creator runs their own Tess on a Raspberry Pi 3, without n8n: one Rust binary, an embedded database, and nothing else to install. It uses about 30 MB of memory while idle, so even a 1 GB board has plenty of room left.

  • No database server needed: RocksDB or SQLite are built in.
  • Native ARM builds: arm64 and armv7 binaries and arm64 Docker images with every release.
  • Pi 4 and 5 too, with room for n8n, PostgreSQL and search on the bigger boards.

Run Tess on a Raspberry Pi →

shell
# On the Pi (64-bit Raspberry Pi OS)
VERSION=0.1.1
curl -LO https://github.com/tessheadless/core/releases/download/v$VERSION/tess-$VERSION-linux-arm64.tar.xz
tar -xJf tess-$VERSION-linux-arm64.tar.xz
cd tess-$VERSION-linux-arm64

cp .env.example .env   # add your secrets
set -a && . ./.env && set +a && ./tess
# → http://raspberrypi.local:8080/admin/

Questions

Is Tess free?

The Community edition is free for personal use. Commercial use needs the Enterprise edition, which also adds advanced features, official plugins and hosting. See Community & Enterprise.

Can AI tools manage my content?

Yes. Tess has a built-in MCP server: connect Claude, Cursor or any MCP client with an API token, and ask it in plain language to create, edit, translate or publish content. It can do exactly what the token's role allows, nothing more.

Which database do I need?

None to start: Tess embeds RocksDB. In production use PostgreSQL, MySQL, MongoDB or DynamoDB, or keep SQLite or RocksDB for small sites.

Can Tess run on a Raspberry Pi?

Yes. Tess's creator runs it on a Raspberry Pi 3. Every release has native arm64 and armv7 Linux binaries and arm64 Docker images, for the Pi 3, 4 and 5. See Raspberry Pi & small devices.

Is there a REST API?

Content is served over GraphQL only. REST endpoints exist for binary payloads: media uploads and downloads, plugin modules.

Can I move my models from another CMS?

Describe them in the tess-transfer YAML format and import them in one command. Each comparison page explains how a model maps to Tess.

Run Tess in one command

docker compose up, open the admin, create your first model.
