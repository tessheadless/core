Serveur MCP intégré

Votre site, géré en parlant à votre IA.

Tess parle le Model Context Protocol, le standard ouvert qu'utilisent les assistants IA pour travailler avec des outils. Connectez Claude, Codex, OpenCode, Pi ou tout client MCP en deux minutes, puis demandez en langage courant : « rédige un article sur notre nouvelle version », « corrige les fautes de la page des tarifs », « quels produits n'ont pas d'image ? ». Aucun plugin à installer, aucun code à écrire.

Ce que vous pouvez demander

Votre assistant lit d'abord vos modèles de contenu : il connaît vos champs, vos relations et vos composants sans aucune configuration. Ensuite, il travaille comme un rédacteur qui ne se fatigue jamais :

  • Écrire : « Rédige trois articles de blog à partir de ces notes de version, avec un résumé et des tags. »
  • Modifier en masse : « Toutes les descriptions de produits de plus de 300 mots : raccourcis-les en gardant le ton. »
  • Vérifier : « Quelles pages publiées n'ont pas de meta description ou pas d'image de couverture ? »
  • Modéliser : « Ajoute un type de contenu FAQ avec une question, une réponse et une catégorie. » (avec un jeton Admin)
  • Publier : « Publie les brouillons que j'ai approuvés ce matin. »
  • Répondre aux questions : « Combien d'articles avons-nous publiés chaque mois cette année ? »

Il fonctionne avec chaque modèle de contenu que vous créez, dès sa création : le serveur MCP expose toute votre API GraphQL à travers deux outils génériques, get_schema et graphql_query.

Prêt en deux minutes

  1. Activez-le dans les réglages du serveur : TESS_MCP=true.
  2. Créez un jeton d'API pour votre assistant dans l'admin (API tokens), avec le rôle dont il a besoin : Contributor pour écrire des brouillons, Member pour la lecture seule.
  3. Ajoutez Tess à votre client IA : l'URL de votre serveur, et le jeton dans un en-tête Authorization: Bearer, comme ici. Claude Code, OpenCode, Codex et Pi le prennent chacun en une ligne de configuration.

C'est tout : votre assistant voit maintenant votre contenu, avec exactement les droits de son jeton. Pour les clients qui ne lancent que des programmes locaux, comme Claude Desktop, la commande tess mcp fait la même chose grâce à un petit proxy local.

Une IA qui travaille pour vous, pas dans votre dos

Donner à une IA l'accès à votre site ne doit pas vouloir dire en perdre le contrôle. Avec Tess, ce n'est pas le cas :

  • Les mêmes règles pour tous. L'assistant utilise un jeton d'API, et Tess applique le rôle et la portée de ce jeton à chaque appel. Un jeton Member lit ; un jeton Contributor écrit des brouillons, uniquement dans les types de contenu que vous autorisez.
  • Le dernier mot reste humain. Avec les workflows de relecture, les modifications de l'IA sont des brouillons soumis à relecture : votre équipe les approuve avant toute mise en ligne.
  • Tout est tracé. Chaque modification enregistre son auteur : vous savez toujours ce qu'a fait l'assistant, et vous pouvez révoquer son jeton en un clic.
  • Vos données restent à vous. Tess tourne sur vos serveurs et ne parle qu'au client IA que vous connectez, avec seulement le contenu que son jeton peut atteindre.

Questions sur l'IA et le MCP

Quels outils d'IA fonctionnent avec Tess ?

Tout client compatible avec le Model Context Protocol : Claude Code, Claude Desktop, OpenCode, Codex, Pi, Cursor et d'autres. Les clients qui acceptent les serveurs distants se connectent directement à https://votre-serveur/mcp, avec votre jeton d'API dans un en-tête Authorization: Bearer ; les autres, comme Claude Desktop, lancent le proxy local tess mcp. Le guide MCP (en anglais) donne la configuration de chacun.

Comment mon assistant IA se connecte-t-il à Tess ?

Avec un jeton d'API que vous créez dans l'admin. Le client l'envoie dans l'en-tête Authorization: Bearer de chaque requête : Tess sait ainsi quel jeton, et quel rôle, appelle. Gardez-le dans une variable d'environnement plutôt que dans un fichier de configuration, et révoquez-le en un clic si besoin. Sans jeton, un assistant ne peut lire que le contenu publié.

Le serveur MCP fait-il partie de l'édition Community ?

Oui. Il est intégré à Tess, dans toutes les éditions : pas de module complémentaire, pas de service en plus. Il reste désactivé tant que vous n'avez pas défini TESS_MCP=true.

L'IA peut-elle supprimer ou abîmer mon contenu ?

Seulement si vous lui donnez un jeton qui le permet. Utilisez un jeton Contributor limité à quelques types de contenu, et activez les workflows de relecture : l'IA écrit alors des brouillons que votre équipe relit et publie.

Est-ce que ça marche avec mes propres modèles de contenu ?

Oui, avec tous, dès que vous les créez. L'assistant lit d'abord votre schéma : il n'y a rien à configurer par modèle.
