Tess ou Strapi

CMS headless open source (Node.js)

Le CMS headless open source le plus populaire, construit sur Node.js, avec une API REST et un plugin GraphQL.

Côte à côte

Tess comparé à Strapi
CritèreTessStrapi
Environnement d'exécutionUn seul binaire RustApplication Node.js (TypeScript)
Modèles de contenuCréés à l'exécution en production (admin ou API) ; le schéma GraphQL est régénéré en directContent-Type Builder en mode développement ; les modèles sont enregistrés comme fichiers de code et déployés avec l'application
APIGraphQL généré à partir des modèlesREST par défaut, GraphQL via un plugin officiel
Bases de donnéesPostgreSQL, MySQL, SQLite, MongoDB, DynamoDB, RocksDBPostgreSQL, MySQL/MariaDB, SQLite
Workflow de relecturePar type de contenu, dans toutes les éditionsBrouillon et publication inclus ; workflows de relecture dans les offres payantes
PluginsModules WebAssembly isolés, installés à l'exécutionPaquets Node.js exécutés dans le processus de l'application, vaste marketplace
LocalisationPas encore de localisation du contenu champ par champInternationalisation du contenu intégrée
HébergementAuto-hébergé : Docker, VM, Kubernetes ou AWS LambdaAuto-hébergé ou Strapi Cloud
LicenceCommunity (usage personnel) / Enterprise (usage commercial)MIT pour la Community Edition ; offres payantes pour les fonctionnalités entreprise

Choisissez Strapi si…

  • Vous voulez une grande marketplace de plugins et une large communauté.
  • Vous avez besoin de contenu localisé dès aujourd'hui.
  • Votre équipe préfère personnaliser le CMS lui-même en JavaScript/TypeScript.

Choisissez Tess si…

  • Les rédacteurs ou les admins doivent modifier les modèles en production, sans redéploiement.
  • Vous voulez une API GraphQL-first sur MongoDB, DynamoDB ou une base embarquée.
  • Vous voulez un workflow de relecture sans offre payante, ou tourner sur AWS Lambda.

Passer de Strapi à Tess

Les types de Strapi se traduisent directement dans Tess : string/text → TEXT, richtext → MARKDOWN, blocks → JSON, enumeration → ENUM, relation → RELATION, media → RELATION vers Asset, component → COMPONENT, dynamiczone → DYNAMIC_ZONE. Écrivez vos modèles au format YAML de tess-transfer et importez-les en une commande, puis copiez les entrées via l'API GraphQL.
