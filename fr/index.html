CMS headless · Rust · GraphQL · MCP

Chaque entrée est une tesselle. Vos applications sont la mosaïque.

Tess est un CMS headless auto-hébergeable, en un seul binaire Rust. Définissez vos modèles de contenu à l'exécution et obtenez aussitôt une API GraphQL typée, sur la base de données que vous utilisez déjà. Et gérez le tout en parlant à votre assistant IA, grâce au serveur MCP intégré.

Démarrer en 5 minutesComparer avec d'autres CMS
graphql
query {
  posts(where: { title_contains: "tess" }, first: 3) {
    total
    items {
      title
      publishedAt
      authors { name }
    }
  }
}

Gérez votre site en parlant à votre IA

Demandez à Claude, Cursor ou tout client MCP d'écrire, de modifier et de publier votre contenu : Tess parle le Model Context Protocol dès l'installation. Votre assistant découvre seul vos modèles de contenu, puis lit et écrit avec la même API et les mêmes droits que vos applications.

  • Ni plugin, ni code d'intégration : activez-le avec TESS_MCP=true et ajoutez une entrée à votre client IA.
  • Sûr par défaut : donnez à l'assistant un jeton Contributor et il ne pourra écrire que des brouillons, que votre équipe relit et publie.
  • Fonctionne avec chaque modèle que vous créez, dès sa création.

Tout ce dont une équipe éditoriale a besoin, rien à reconstruire

Tess regroupe les règles métier en un seul endroit : l'API GraphQL, l'interface d'admin, les envois de fichiers et les plugins se comportent tous de la même façon.

  • Piloté par l'IA

    Un serveur MCP intégré permet à Claude, Cursor et tout client MCP de lire vos modèles, puis de créer, modifier et publier du contenu en langage courant, avec les mêmes droits que l'API.

  • Modèles à l'exécution

    Créez des types de contenu dans l'admin ou par l'API, en production. Le schéma GraphQL est régénéré à la volée : ni rebuild, ni redéploiement.

  • GraphQL d'abord

    Requêtes typées, filtres, tri, pagination, relations et mutations générés pour chaque modèle, avec l'IDE GraphiQL intégré.

  • Votre base de données

    PostgreSQL, MySQL, SQLite, MongoDB, DynamoDB ou RocksDB embarqué. Chaque backend passe la même suite de conformité.

  • Workflows de relecture

    Brouillon et publication pour chaque entrée, plus un workflow optionnel soumettre → approuver par type de contenu, dans toutes les éditions.

  • Plugins isolés

    Plugins WebAssembly installés par les admins à l'exécution, écrits en Rust, Go, JavaScript et plus, avec délais et limites de mémoire.

Un modèle de contenu, c'est une mutation

Créez un type de contenu et Tess génère sur-le-champ ses requêtes, filtres, tris, pagination et mutations, sur chaque instance.

Vous préférez cliquer ? L'interface d'admin a un éditeur de modèles. Vous préférez les fichiers ? Gardez vos modèles en YAML et importez-les avec tess-transfer.

graphql
mutation {
  createContentType(input: {
    apiId: "Post"
    workflow: true
    fields: [
      { name: "title", type: TEXT, required: true }
      { name: "body", type: MARKDOWN }
      { name: "cover", type: RELATION, relationTarget: "Asset" }
      { name: "authors", type: RELATION, relationTarget: "Author", many: true }
    ]
  }) { apiId }
}

Anecdote : Tess tourne sur un Raspberry Pi 3

La personne qui a créé Tess fait tourner sa propre instance sur un Raspberry Pi 3, sans n8n : un binaire Rust, une base de données embarquée, et rien d'autre à installer. Au repos, Tess utilise environ 30 Mo de mémoire : même une carte de 1 Go garde beaucoup de marge.

  • Pas de serveur de base de données : RocksDB et SQLite sont intégrés.
  • Versions ARM natives : binaires arm64 et armv7 et images Docker arm64 à chaque version.
  • Pi 4 et 5 aussi, avec de la place pour n8n, PostgreSQL et la recherche sur les plus grosses cartes.

Installer Tess sur un Raspberry Pi →

shell
# Sur le Pi (Raspberry Pi OS 64 bits)
VERSION=0.1.1
curl -LO https://github.com/tessheadless/core/releases/download/v$VERSION/tess-$VERSION-linux-arm64.tar.xz
tar -xJf tess-$VERSION-linux-arm64.tar.xz
cd tess-$VERSION-linux-arm64

cp .env.example .env   # ajoutez vos secrets
set -a && . ./.env && set +a && ./tess
# → http://raspberrypi.local:8080/admin/

Questions

Tess est-il gratuit ?

L'édition Community est gratuite pour un usage personnel. Un usage commercial demande l'édition Enterprise, qui ajoute aussi des fonctionnalités avancées, des plugins officiels et l'hébergement. Voir Community et Enterprise (en anglais).

Des outils d'IA peuvent-ils gérer mon contenu ?

Oui. Tess a un serveur MCP intégré : connectez Claude, Cursor ou tout client MCP avec un jeton d'API, et demandez-lui en langage courant de créer, modifier, traduire ou publier du contenu. Il peut faire exactement ce que le rôle du jeton autorise, rien de plus.

De quelle base de données ai-je besoin ?

D'aucune pour commencer : Tess embarque RocksDB. En production, utilisez PostgreSQL, MySQL, MongoDB ou DynamoDB, ou gardez SQLite ou RocksDB pour les petits sites.

Tess peut-il tourner sur un Raspberry Pi ?

Oui. La personne qui a créé Tess le fait tourner sur un Raspberry Pi 3. Chaque version fournit des binaires Linux natifs arm64 et armv7 et des images Docker arm64, pour les Pi 3, 4 et 5. Voir Raspberry Pi et petits appareils (en anglais).

Y a-t-il une API REST ?

Le contenu est servi uniquement en GraphQL. Des points d'accès REST existent pour les données binaires : envoi et téléchargement des médias, modules de plugins.

Puis-je reprendre mes modèles d'un autre CMS ?

Décrivez-les au format YAML de tess-transfer et importez-les en une commande. Chaque page de comparaison explique comment un modèle se traduit dans Tess.

Lancez Tess en une commande

docker compose up, ouvrez l'admin, créez votre premier modèle.
